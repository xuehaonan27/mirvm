## 0. 一句话

M4.3 后线程债务**只剩 denylist 上的三个符号**（pthread_create/join/detach）——真线程的
全部地基（真宿主原子、futex/syscall 直通、Sync 引擎、unwind、堆）已在前四期就位。
M4.4 = **一个新机制（thunk 工厂）+ 一处 per-thread 化（guest TLS）+ 收尾直通**。

## 1. 调研数据

- **threads_spawn 债务表**：3294 instance，含 Trap 仅 19（0.6%）——
  `pthread_create`/`pthread_join`/`pthread_detach`（denylist）各 1 处 + 20 处不可达尾巴。
  threads_channel/sync/time/panic 同形。
- **std 的 pthread 包装形态**（sys/thread/unix.rs 实测）：
  `pthread_create(&native, attr, thread_start, data)`，其中
  `extern "C" fn thread_start(*mut c_void) -> *mut c_void` 是 **std 自己的 Rust fn**
  （引擎视角 = ReifyFnPointer 后的 D4 条目地址）。thread_start 体内：Box 还原、
  stack_overflow Handler 装载（经 sigaction——现 stub 假成功=不装 ✓）、调用户闭包
  （panic 已被 std catch）。**DESIGN §5 的判断实测坐实：std 已把 pthread wrap 好，
  引擎唯一缺口 = FFI 反方向（guest fn ptr 逃逸给 native 要能被 native 调）**。
- **libffi closure**（5.1.1 核对）：`middle::Closure::new(cif, callback, userdata)` →
  `code_ptr()` 真机器码；callback 收 (args 数组, userdata)。签名任意（cif 描述）。
- **TLS 现状**：`ThreadLocalRef` 在 M4.2 单线程物化为普通 static（代码已标注 M4.4 义务）；
  std 的 TLS dtor 注册链：weak `__cxa_thread_atexit_impl` cell=0 → fallback 到
  pthread_key 路径（dtor 是 guest fn ptr——**与 thread_start 同一 thunk 机制**）。
- **corpus 挂死双场景**在 corpus/c_blocking_io.rs、c_net_echo_threaded.rs（阻塞
  read/accept——真线程下天然不挡別的线程，无需引擎动作）。

## 2. 架构决策（请审）

### D1 thunk 工厂 = 本期唯一新机制（vmctx-passing §1 的兑现）

**通用判定**：CallForeign 的实参**类型是 fn ptr**（lower 期从 foreign fn sig 知道）→
签名冻结进 `ForeignSig.thunk_args: Vec<(参数位, 该 fn ptr 的 ForeignSig)>`。执行期：

```
实参值 v = 条目地址？（Module.fn_addrs 反查命中）
  ├─ 是 → thunk_factory.get_or_create(v, sig) → 真机器码地址替换实参
  ├─ v == 0（NULL 回调）→ 原样直传
  └─ 否（已是 native 真码——guest 转传收到的 native 回调）→ 原样直传 ✓
```

thunk（libffi Closure，leak 进程级）入口 = **边界 TLS attach**（JNI 同款，被三条约束
逼定：plain-C 签名无隐藏参 / ctx 每线程一份 / 任意线程可调）：

```
宿主 thread_local TLS_CTX: RefCell<Option<Box<Ctx>>>
thunk(args…):
  TLS_CTX 空 → attach：Ctx::new(&'static Shared)   ← 新 guest 线程的执行态诞生点
  call_fn_addr(ctx, 条目地址, args 按冻结签名搬运) → 返回值按签名写回
```

- 缓存：`Shared.thunks: Mutex<HashMap<(条目地址, 签名), 真码地址>>`——同一 guest fn
  多次逃逸得同一 thunk（fn ptr 相等语义）。Mutex = 状态三分的"显式同步"格，合法。
- `Shared` 提升 `Box::leak` 为 `&'static`（进程级；exit 直通下无需回收）。
- 主线程统一走同一 TLS attach 形态（run_main 入口 attach 一次）——单双线程一条路。
- 线程退出：宿主 thread_local drop 自动清 Ctx（ByteRegion munmap 等）。

**覆盖面**（同一机制三客户）：pthread_create 的 thread_start、pthread_key_create 的
dtor、（选项 B 时）sigaction 的 handler。

### D2 pthread 直通清单变更

denylist 移除 `pthread_create/join/detach` → 走通用 CallForeign（join/detach 纯直通，
tid 是真 pthread_t——tier-0 的 into_pthread_t 教训在此终局）。**保留** denylist：
`pthread_exit`（glibc 强制 unwind 会绕过 FrameGuard——std 不用它）、`pthread_atfork`、
fork/exec/setjmp 系。

### D3 guest TLS per-thread 化

- lower：`ThreadLocalRef(def_id)` → 稠密 `TlsId` + **模板物化**（初始字节进冻结区一份）
  → `Module.tls: Vec<TlsSlot{template, size, align}>`；IR `Rvalue::TlsRef{id}`。
- engine：`Ctx.tls: Vec<u64>`（lazy）——首访 heap::alloc + memcpy 模板；地址即真地址。
- **v1 记账：guest TLS dtor 不跑**（pthread_key_create 直通时 dtor 参数置 NULL）。
  原因：guest dtor（thunk）与宿主 thread_local drop 的线程退出顺序 unspecified——
  dtor 跑时 Ctx 可能已亡，attach 重建会读到全新 TLS 实例（错值比泄漏贵）。
  代价：每线程每 TLS 一小块泄漏 + TLS 值的 Drop 副作用缺失（threads_* 五用例实测
  不依赖；println/channel/mutex 均不经 TLS dtor）。真 dtor = M4.4 收尾可选块
  （方案：Ctx 改 pthread_key 自管、控制 dtor 相对顺序）。

### D4 原子与 fence

原子已是真宿主指令（M4.1，全 SeqCst——最强序在 RAM non-det 包络内，m4-plan §6 弱序
特殊化明确不做）。本期补：`atomic_fence → std::sync::atomic::fence(SeqCst)`、
`atomic_singlethreadfence → compiler_fence(SeqCst)`（M4.2 的 nop 复查义务兑现）。

### D5 signal（请裁：A/B）

- **A（推荐 v1）**：全信号维持 stub（假成功不装）。threads_* 与挂死双场景不依赖信号；
  std 的栈溢出 handler 不装 = 深度守卫已给引擎级防护。signal 真装载挪 M4.5 前
  （corpus signal 探针逼出时），彼时 thunk 工厂已就绪、增量只是"从 stub 表移到直通"。
- **B（完整）**：除 SIGSEGV/SIGBUS 外 sigaction 直通 + handler thunk 化（corpus §2.3
  本期兑现）。代价：信号可在任意线程任意时点重入解释器（async-signal-safety 由 guest
  负责，与 native 同），测试面大。

### D6 gate 载体

- threads_* 五用例进 `tests/diff_vm.sh`（预期红注释摘除）。
- 挂死双场景 + rayon：经 frontmatter/cargo 形态——**runner 加 `MIRVM_ENGINE=vm` 环境
  变量透传**（一行改动，cargo 全接线仍归 M4.5）。
- TSan：tsan harness 增多线程用例（手构 Module：8 宿主线程共享 Shared 各自 Ctx 跑
  原子自增 + thunk 工厂并发 get_or_create）——spike4 义务的 M4 真身。

## 3. 施工顺序（每步可验）

0. Shared `&'static` 化 + 宿主 TLS attach 形态统一（run_main/run_export 走 attach）
   —— 单线程全量回归绿（纯重构步）
1. thunk 工厂 + CallForeign 实参 fn-ptr thunk 化 + denylist 移除三符号
   —— **threads_spawn 差分绿**（第一根真线程跑通）
2. guest TLS per-thread（TlsRef/模板/Ctx.tls；pthread_key dtor 置 NULL）
   —— threads_channel/sync/time 绿（panic_count 等 std TLS 正确性）
3. fence 补真；threads_panic 绿（子线程 panic→join Err 全链）
4. TSan 多线程用例 + corpus 挂死双场景 + rayon（runner 透传）+（若裁 B）signal
5. `tests/m4_gate4.sh`（diff_vm 全量含 threads + TSan + 双场景）+ m4-log + 复测

## 4. 风险与缓解

- **pthread_key dtor 顺序**（D3 已记账 v1 规避）。
- **子线程首次 heap 分配**：mimalloc per-thread heap 惰性初始化线程安全 ✓（上游保证）。
- **thunk 并发创建**：Mutex 缓存；Closure leak 无 UAF。
- **子线程 guest panic 穿出 thread_start**：std 已 catch；万一穿出 thunk = 宿主线程
  unwind 到 pthread 底 abort（与 native 一致）。
- **TSan 通道**：tsan crate 已含 libffi/libmimalloc 依赖；引擎核心零 rustc_private
  不变（纯度门禁盯着）。
- **深度守卫 per-Ctx**：每线程独立 8000 帧上限 ✓ 自动正确。

## 5. 不做（本期）

弱内存序特殊化（映射宿主 SeqCst 即合法）、pthread_exit/fork/atfork（denylist 保持）、
guest TLS dtor（v1 记账，见 D3）、（若裁 A）signal 真装载、cargo 全接线（M4.5）、
线程栈大小的 guest 控制精确化（pthread_attr_setstacksize 直通即生效——但解释帧实际
消耗在**宿主**线程栈，guest 指定值语义近似，记录偏差）。

## 6. 退出判据（对齐 m4-plan 总验收）

threads_* 5/5 差分绿 + **c_blocking_io 与 net_echo_threaded 通过**（tier-0 挂死的两个）
+ TSan 多线程用例零警告 + rayon 秒级 + 全量回归无损（gate0-2/diff/diff_vm/spikes/纯度）。
