## 0. 一句话

M5.0 清掉 inline asm 三面孔后，四个红用例的下一层全落到 `llvm.x86.*`。M5.1 目标是把
这层和 blake3 的静态归档阻塞清零，并在可信 oracle 下让相关用例转绿；是否能宣称整个 corpus
零例外还取决于 signal 等非 M5.1 语义缺口是否已经真实实现。
核心手法不是把全部 `llvm.x86.*` 统一塞进 asm-stub，而是**按语义分流**：标量进位/xgetbv
走固定 builtin；解释器的 pshufb/SHA-NI 采用 tcx-free 宿主 `std::arch` target-feature helper；
可移植的 `simd_*` 继续走引擎已有向量语义。原先“pshufb 逐 lane + SHA 走通用 asm-stub 向量
ABI”的提案保留在 D7b 作为被替代方案；方法级 JIT 以后仍可分别降 CLIF/单指令 asm。

## 1. 调研数据（2026-07-12 实测）

### 1.1 头号发现：面分两个机制（simd_* 已覆盖 / llvm.x86 是真缺口）

`_mm_add_epi32`/`xor`/`cmpeq`/`and`/`or`/`set1`/`loadu` 等在 MIR 层降为 **`simd_*`
rustc intrinsic**（`_mm_add_epi32` → `simd_add`），**引擎 M4.1 起已覆盖**
（`expand_simd`：eq/ne/lt/le/gt/ge/and/or/xor/add/sub/bitmask/reduce/shuffle/splat）。
当前已实测的 `llvm.x86.*` foreign call 包括 pshufb、SHA-NI（sha256rnds2/msg1/msg2）、
xgetbv、addcarry/subborrow；其中 pshufb 虽没有通用 `simd_shuffle` 直接替代，cg_clif 仍可用
逐 lane CLIF 表达，并不需要 asm。当前 nightly 的 SSE/AVX movemask 已经表现为
`simd_lt + simd_bitmask`，memchr 2.8.3 源码中也未发现 pshufb，因此不能把 movemask/pshufb
预写成 ecosystem 的必经缺口。带立即数的具体面同样应以 MIR 实测为准，不能从首批样本外推
“全部无立即数”。

### 1.2 第二发现：--vm-stats 系统性低估面（必须增量发现）

初始逐红用例 `--vm-stats` 各只报**一个** llvm.x86（numbigint=addcarry.64、blake3=xgetbv、
sha2=ssse3.pshuf.b.128）。原因：特性检测（cpuid/xgetbv）后走 **fn-ptr 间接派发**
选 SIMD 实现，而 vm-stats 可达 BFS 有"fn-ptr 无出边"盲点（AGENT-HANDOFF §8 已记）
——派发之后的 SIMD 内核面看不见。**推论：静态枚举必再低估**（M5.0"修完撞下一层"
的同一陷阱）。故 M5.1 **不承诺“实现初始枚举的 N 个 intrinsic”**，结构 = 实现-重跑-再补。

xgetbv 实现后的第一轮滚动再次验证该判断：blake3 前移到静态 archive 符号，ecosystem
前移到 `simd_insert`，sha2 当时前移到 pshufb；随后向量 helper 切片已使 sha2 转绿。
旧失败原因必须从 expected-red 清单移除。

### 1.3 逐红用例的真实面（源码盘点，非 vm-stats）

| 用例 | 特性检测 | SIMD 内核路径 | M5.1 处置 |
|---|---|---|---|
| **numbigint** | 无 | `addcarry.64` + `subborrow.64` 标量进位链 | **已实现 builtin，native 差分通过，当前转绿** |
| **blake3** | xgetbv **已通过** | **`.S` 静态归档**符号（build.rs `blake3_sse2_ffi` cfg，Rust 侧 extern "C" 到 `blake3_hash_many_*`） | **受约束 archive 装载已接入；native 三行 hash 一致，当前转绿** |
| **sha2** | cpuid（cpufeatures，无 xgetbv） | pshufb + SHA-NI | **stdarch helpers 已接入；native 差分与两个标准 SHA256 输出通过，当前转绿** |
| **ecosystem** | xgetbv **已通过** | `simd_insert/extract`、`simd_shl/shr`、`vzeroupper` | **补面后 debug/release 完整通过，当前转绿** |

**关键**：blake3 的 SIMD 是**静态归档不是 intrinsic**——它的 intrinsic 面就 xgetbv
一个，主体是 D2。sha2 面最重（SHA-NI 专用指令 + ymm）。

### 1.4 cg_clif 先例（逐 intrinsic 处置核对）

`intrinsics/llvm_x86.rs`：pshufb 走逐 lane 的 `pshufb_swizzle` CLIF 降低；
`llvm.x86.sha256rnds2`/`aesni.aesenc` 等无 CLIF 对应的，
cg_clif **本身就用 asm wrapper 兜底**（`InlineAsmTemplatePiece::String("sha256rnds2
xmm1, xmm2")`）——**M5.1 的合成 asm-stub 与 cg_clif 同构**，非独创。sha256rnds2 有
**隐式 xmm0 第三操作数**（cg_clif 注释"Implicit argument"），需特殊处置。

## 2. 决策（最终结果；保留被替代提案）

### D7a llvm.x86 拦截分流（`lower/mod.rs:307`）
最终落地为 `llvm.x86.*` 查处置表分流：向量硬件按条目选择固定向量 builtin（D7b），
标量进位/xgetbv 走 builtin（D7c）；未登记的名称仍 Err（Trap 诊断，按需再登记，
数据驱动）。非 x86 的 `llvm.*` 维持 Err。

### D7b 向量 llvm.x86 → tcx-free 宿主 stdarch helper（最终选择，已集成验收）

`src/vm/engine/x86.rs` 提供窄而显式的 helper（**产品接入已验收**）：

- `pshufb128` / `pshufb256` 分别用 `#[target_feature(enable="ssse3"/"avx2")]` 和宿主
  `_mm[_256]_shuffle_epi8`；256 位保持两个独立 128-bit lane。
- `sha256msg1` / `sha256msg2` / `sha256rnds2` 用 `#[target_feature(enable="sha")]` 的
  stdarch intrinsic，执行真实宿主 SHA 指令；stdarch 签名承担 rnds2 隐式 xmm0 的机器细节。
- helper 接受 guest place 的地址并整体搬运 16/32 字节，不让通用标量 `Operand` 假装承载向量。
  guest 自己的 CPUID 分派保证只在宿主支持相应 feature 时进入；独立 known-vector 单元测试
  已通过；lower/interpreter 地址式宽值接入、`m51_x86_vectors` native 差分和 c_sha2 两个标准
  SHA256 输出也已通过。tracer 对 pshufb 与 SHA 子特性分别 PASS/SKIP，
  不会在宿主缺 SHA-NI 时把整个 vector probe 冒充 PASS；当前路线转为 active。

**为什么替代原提案**：初稿计划 pshufb 按 cg_clif 逐 lane 表达、SHA 复用 M5.0 asm-stub，
并为此扩一套通用 asm-stub 16/32-byte ABI。复核后发现解释器只需少数固定指令；宿主 stdarch
helper 同样执行真实宿主指令，却无需扩通用 wrapper 寄存器/隐式操作数协议，代码更小、类型更
明确。这个选择只规定解释器语义路径，不封死 M5.3 JIT 继续采用 CLIF lane 或单指令 asm。

【保留的旧方案】通用 asm-stub 向量 ABI 在未来出现大量文本 asm 客户时仍可重开；触发器是
固定 stdarch helper 数量显著膨胀，或某指令无可用 stdarch/CLIF 表达且需要动态模板。

### D7c 标量 llvm.x86 → 引擎 builtin
`addcarry.64`/`subborrow.64`（进位/借位链）已实现为精确 builtin（`a+b+carry`，
`u128` 检测进位），比 asm-stub（`adc` 需管 CF flag，wrapper prologue 已扰 flag）
**更简更稳**；native 差分和 c_numbigint 已通过。xgetbv 最终也作为 scalar builtin 落地：
解释器以宿主 inline asm 执行 `ecx→edx:eax`，在 guest 正常 CPUID guard 后调用；独立 tracer
确认与 native 输出一致。它没有为了一个固定纯寄存器指令绕经加载相 asm-stub 工厂。

### D7d simd_* 覆盖验证 + 按缺补
引擎 `expand_simd` 已覆盖主面（§1.1）。sha2/memchr 实测若暴露缺口（如特定 lane 宽
的 add_epi64、simd_shuffle 的边角），按实测补——**不预支未触发的**（M4.5 教训反用）。

### D2 静态原生归档装载（已完成的受约束 Linux/ELF 垂直切片）

- lower 遍历 local + used crates 的 `tcx.native_libraries`，只处理经过 cfg 求值的 Static；
  filename/verbatim 使用 rustc metadata 与 `staticlib_components`，从 native search paths 找归档。
- 每个 archive 独立执行
  `cc -shared -Wl,-z,defs -Wl,--whole-archive <archive> -Wl,--no-whole-archive`；结果进入
  `Module.required_native_libs`；执行相必须在任何 RTLD_DEFAULT/dlsym 查找前以
  `RTLD_NOW|RTLD_GLOBAL` 加载成功。`dlopen` 失败保留路径和 `dlerror` 立即终止，
  不能退化命中系统同名库。
- 缓存键包含 recipe/实际 flags、target triple、cc version + dumpmachine、archive bytes；临时文件
  + rename 原子发布。`--no-whole-archive` 不可省，否则实测会把隐式 libgcc 拉入并重复定义。
- 明确拒绝非 Linux/ELF、thin archive、`.init/.fini` 与 ctor/dtor sections（含优先级
  suffix）、非 PIC relocation、未闭合/跨 archive
  依赖与顺序、跨 archive 重名动态导出、与 `RTLD_DEFAULT` 既有同名符号、`export-symbols`
  modifier；它不是通用 native linker。
- 12 个 archive 定向单测覆盖 dlsym 可见性、缓存身份和拒绝路径，另有
  2 个 FFI 测试锁住 optional/required 加载差异；blake3 的两个 build.rs archives 转换
  成功，`c_blake3` 与 native 三行 hash 逐字一致。

保留的未来问题：需要支持上述拒绝面时，先定义多 archive link plan、constructor 生命周期和
modifier 等价语义，不能悄悄放宽 `-z defs`。

### D-scope 增量发现（非大爆炸）
§1.2 定：vm-stats 低估 → 每步实现一批、重跑红用例看下一层、再补，直到 M5.1 负责的
客户链全绿；signal 等非本期能力单列 XFAIL。
gate = **用例绿**，不是"实现清单"。每步 commit 带"推进到哪一层"的透明记账（M5.0
复审教训：预期红判据随前沿滚动）。

## 3. 实际完成顺序（增量，每步一个红用例推进/转绿）

1. **标量进位解锁（已完成）**：addcarry/subborrow builtin + native differential probe →
   **numbigint 绿**。
2. **特性检测续推（已完成）**：xgetbv（ecx→edx:eax）已与 native 差分；滚动结果为
   blake3=静态 archive、ecosystem=`simd_insert`。
3. **x86 helper + 宽值接入（已完成）**：lower/interpreter 用地址式宽值通道调用
   pshufb128/256 与 SHA helper；m51_x86_vectors native 差分通过。
4. **SHA-NI 集成（已完成）**：sha256rnds2/msg1/msg2 共用 stdarch helper；
   **sha2 绿**（两个标准 SHA256 输出正确）。
5. **D2 归档装载（已完成）**：成对 whole/no-whole-archive + `-z defs`，明确拒绝未定义面；
   **blake3 绿**（三行 hash 与 native 逐字一致）。
6. **ecosystem 收口（已完成）**：补 `simd_insert/extract`、signed/unsigned `simd_shl/shr`
   与无 RAM 状态效果的 `vzeroupper` hint；debug/release ecosystem 完整通过，**diff_cargo
   已滚动为 3/3**。
7. **gate 滚动 + 收笔（已完成）**：M5.1 自己的 expected-red 已清空；addcarry、xgetbv、
   x86_vectors、simd_insert/extract、simd_shift、vzeroupper 六个 release tracer 均已与
   native 对拍。原拟用单一 `demo/simd_probe.rs` 覆盖全部新增面的计划，实际拆成这六个
   定向 tracer 脚本；x86_vectors 再将 pshufb/SHA 分成两个子断言。最终复审后
   full gate5 为 40 PASS / 2 XFAIL / 0 SKIP / 0 FAIL，m5-log、HANDOFF 和
   current-status 已同步收笔。

## 4. 风险与缓解

- **面比预估大（§1.2 低估律）**：增量结构本身是缓解——每步实测下一层，不靠静态枚举；
  ecosystem 已按该方法收口，未来新增客户继续沿用。
- **向量操作数 ABI**：lower 必须按地址/size 把 guest place 交给 helper，不能经 u64 标量
  `Operand` 截断；c_sha2 + known-vector 双层把关。
- **sha256rnds2 隐式 xmm0**：由 stdarch helper 的类型化调用处理；差分对拍 native SHA-256
  哈希值把关（错一位立现）。
- **D2 拒绝面**：当前以 `-z defs`、readelf 与 metadata 检查响亮拒绝非 PIC、依赖不闭合、
  constructor、thin 与 export-symbols；未来若扩面，必须先有对应生命周期/link-plan probes，
  不能只凭 blake3 成功宣称通用。
- **防静默错值**：向量 intrinsic 全程差分对拍真 native（哈希/正则输出逐字节）；
  未登记 intrinsic 响亮 Trap 非静默。

## 5. 不做（本期）

方法级 JIT（M5.3；本期仍解释器，asm-stub 是解释器可直调的机器码）、非 x86 SIMD、
带立即数 asm 操作数（llvm.x86 面无，§1.1）、AES/其他未被红用例触发的 llvm.x86
（数据驱动，触发再登记）、mode B。

## 6. 退出判据（最终诚实口径）

   子脚本失败能传递到顶层状态码；

   signal 与 backtrace 若尚未实现，必须维持原因锁定的 expected-red，因此不得宣称
   corpus “全绿零例外”；只有它们也有真实语义时

③ 六个 release tracer 脚本（addcarry、xgetbv、x86_vectors、simd_insert/extract、
