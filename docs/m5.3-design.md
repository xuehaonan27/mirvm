## 0. 结论速览（请裁 J1–J3）

- **J1 共享基座**：per-fn 状态格 + 单一派发点 `call_guest` + PLT 槽表 + 调用计数
  ——D4/D5 原案在 S4 合并 FuncId 空间上的落地。这是 JIT 分层的地基；无论 S3 形态
  如何裁决，基座都要建（M5.3a 片）。
- **J2 S3 终裁建议**：**调用时懒降低（coldstart-research V3 原形态）不建**。三重
  反对：① 顶撞 D3 架构承诺（tcx 永不出执行相；"执行相必须等 tcx.finish/诊断收尾/
  compiler drop 完成"是 2026-07-13 为诊断正确性专门定的既有决策）；② 破坏 L2 洁净
  快照契约（engine 一启动 statics 即被改写，快照必脏）；③ S4 后其脚本收益只剩
  ~25ms（delta lower 仅 31ms）。其真正标的——**ecosystem 类 registry 依赖的
  988ms**——改由 **S3′ = 依赖成像**吃掉：把 S4 底座机制推广到每个 registry 依赖，
  在该依赖的 cargo 构建会话内（S2 的 DepCallbacks 已持 tcx 且已调
  `collect_and_partition_mono_items`）就地降低出该 crate 的 image。tcx 合法在场、
  快照天然洁净、跨项目可共享（L1 级缓存）、零首调抖动——native rlib 模型的解释版
  镜像，也是 mode B 的机内半成品。
- **J3 施工顺序建议**：**M5.3 JIT 先行**（engine 相 1.4s/eco、30–70×/真实项目，是
  当前最大剩余成本），S3′ 依赖成像随后（988ms）；两轨共享 J1 基座与 S4 机制，互不
  阻塞，可穿插。

## 1. 输入事实（实测/源码级，写入即锚点）

- **S4 后冷启动账本**：脚本纯冷 104–164ms（lower 31–76ms）；eco 冷 runner =
  frontend 107 + **lower 988（registry 依赖份额）** + engine 1407ms；warm 1.5s
  （engine 支配）。执行集/降低集 = 7.6–29%（片3 探针）。
- **性能锚点**：fib(32) 解释 0.94s vs native 8ms ≈ 120×；spike5 真 Cranelift 直调
  距 native 2.1–2.2×（fib(30)：JIT-R 5.47ms / JIT-P 5.90ms / native 2.63ms）；
  真实项目 ripgrep/tokei 解释 ≈ native 30–70×。
- **spike5 已证**：i2c/c2i/cc→cc 直调、P/R 两约定（R 快 ~8%，vcode 坐实 threading
  税）、eh_frame 逐 FDE 自注册（libgcc 语义 + CIE 判别）后 unwind 穿真 JIT 帧、
  gimli 0.33 版本对齐、JITModule 无逐函数释放、feature 门保 TSan 通道。
- **派发收拢面**：`interp_frame` 产品调用点 6 处——Call（interp.rs:2317）/
  CallIndirect（:2406）/ CatchUnwind 回调 call_fn_addr（:2110）/ run_main（:2810）/
  run_export（:2833）/ thunk 蹦床（thunks.rs:65，signal/atexit 经 thunk 工厂同道）
  ——与 D4 清单一致；另 tsan_mt.rs:94 为 TSan harness 自用（见 §7 Q4）。
- **eager 全量 JIT 不可行**（D4 既证）：3027–13209 instance × ~0.3–1ms ≈ 1–13s。

## 2. J1 共享基座（M5.3a：纯解释语义不变的地基片）

### 2.1 per-fn 状态格

```
Bytecode ──计数过阈值──► Compiling ──发布──► Machine
   │  （解释执行照旧）        （解释执行照旧）      （PLT 槽 = fast 入口）
   └── Trap 体：永不入格（计数豁免；Trap = 诊断路径，编译无意义）
```

格是**二态 + 过渡**（Bytecode/Machine）。原 V3 设想的 `LowerStub` 态按 J2 裁定
不进产品；状态编码预留扩展位（S3′ 若来也不需要它——image 函数装载即 Bytecode）。

### 2.2 单一派发点 call_guest

`call_guest(ctx, FuncId, &[u64]) -> (u64, u64)` 收拢上述 6 处调用点：查 per-fn
原子 code-ptr（PLT 槽）——非空即 i2c 直调 packed 入口；空则计数 +1（Relaxed），
过阈值（v1 = 1000，CLI 可调）投递编译队列，然后 `interp_frame` 照旧。
thunk/CallIndirect/CatchUnwind 零改动自动受益（D4 原话兑现）。

### 2.3 PLT 槽表与发布协议

- 槽表 = `Vec<AtomicU64>`，索引 = **S4 合并后的绝对 FuncId**（base++delta 单表，
  域无关——base 的热函数（fmt/iter/alloc 机器）与 delta 同等 tier-up）。
- 槽初值 0（= 解释）；编译完成 Release 写 fast/packed 入口对，调用方 Acquire 读
  ——协议只有一次原子指针交换（D4：简单到不需要 TSan 佐证；TSan 通道本就不编
  cranelift feature）。
- cc→cc 经槽表间接（D5 原案：调用点恒定 `load 槽 + call reg`；槽内蹦床 c2i →
  编译后原子换 fast 入口）。

### 2.4 计数器

side-table `Vec<AtomicU32>`（不塞 FuncBody——缓存行独立、L2 序列化零感知）。
Relaxed 计数允许竞态丢计（无害：只影响触发时刻）。

### 2.5 机器码不入缓存（v1 记账）

L3（JIT 码缓存）维持 D9c 禁令期语义：进程内易失。理由不变：机器码含进程级绝对
地址（PLT 槽地址、helper 地址），且 T→R 制度翻转按 D5 是整缓存重编。mode B 期
与"零拷贝字节码布局"（S4 片6c 裁剪项）同题重开。

## 3. J2 论证：S3 的三条候选形态与终裁

### 3.1 候选 A：调用时懒降低（V3 原形态）——**不建**

机制：delta 函数首见只占 FuncId，首调触发降低。三重反对，每条都是既有契约级：

1. **D3 架构承诺**：`tcx` 永不出执行相；JIT 吃字节码不吃 MIR 的三条理由（架构
   纪律 / mode B 白拿 / 字节码本为此设计）对 lower 同样成立。首调降低要求 rustc
   会话活到运行期——而"callback 只做加载相；执行相必须等 tcx.finish、诊断收尾和
   compiler drop 全部完成"是 2026-07-13 修 runner 告警泄漏时**专门定型**的决策
   （current-status §4；"直接 process::exit 是已被取代的中间方案"）。倒回去 =
   重开诊断收尾、进程退出、TRACK_DIAGNOSTIC 窗口三个已关账的正确性面。
2. **L2 洁净快照契约**：store 语义 = "lower 刚完成、guest 未运行的洁净态"（M6
   片2）。懒降低下模块在运行期持续生长且 statics 已被 guest 改写——要么放弃冷跑
   入账（warm 永不出现），要么把 L2 改成"运行后累积快照"（脏 statics 混入 =
   错值级；分离 statics/const 双 arena = 大手术），要么背景子进程重降一遍（诚实
   但双倍 CPU）。三条出路没有一条不伤现有契约。
3. **收益已塌缩**：S4 后脚本 delta lower 31ms（懒化上界省 ~25ms）；eco 的 988ms
   是 registry 依赖——候选 C 吃得更干净且可跨项目缓存。剩余卖点只有"跳过永不
   执行的 71–93% 函数体"的 CPU 节省——以首调延迟抖动 + 两条契约破口为代价，
   不成交。

**重启触发器**（记档）：若未来出现"单次运行、超大 delta、不可预降"的负载形态
（如 REPL/宏展开型动态代码），以彼时数据重开；届时先决条件 = L2 statics/const
分域 + 会话生命周期重设计两个前置件单独立项。

### 3.2 候选 B：流式降低（eager 后台 drain + 首调阻塞）——**否决**

engine 与 lower 并发，首调未就绪函数阻塞在 per-fn Once 上。保住了"最终全量降低"
但 **L2 快照冲突与 A 完全同构**（engine 启动即写 statics/argv 已终结化），且 tcx
生命周期问题只是从"无限期"缩为"drain 期间"——两条契约仍破。收益上界 =
`sum → max(lower, engine)`，对 eco ≈ −900ms——与候选 C 相当但 C 无契约破口、
还白得跨项目共享。无独立存在价值。

### 3.3 候选 C：依赖成像 S3′（**建议采纳**）

**一句话**：S4 对 sysroot 干了什么，S3′ 就对每个 registry 依赖干什么——在**它自己
的 cargo 构建会话**里。

- **在哪降低**：S2 的依赖会话（wrapper in-process + `-Zno-codegen`）。DepCallbacks
  **已经**调 `collect_and_partition_mono_items`（post-mono 错误面保真）——该集合
  正是 native 给这个 rlib codegen 的 mono item 集（D1"正确性白拿"的同构延伸）。
  就地接 `lower_for_base_build` 同款管线产出 image：**tcx 合法在场（本来就在
  会话里）、快照天然洁净（无 guest 运行）、D3 边界零伤**。
- **image 内容** = 该 crate mono 集 − 栈下已有（多 image 联合查找 = S4 Linker
  base-maps 的多源推广：`base_fns` 等四表从"单底座"变"底座+已装 image 链的并集"）。
- **地址分配**：每 image 一个固定域——样条 `0x6A00_0000_0000 + k·2^34`（16 GiB
  步距，容 ~1500 个 image 不触 0x7f 带；FROZEN_CAP 256 MiB 远小于步距）。
  MAP_FIXED_NOREPLACE，被占回退 = 本会话不产 image（既有契约）。k 由 lockfile
  拓扑序分配，随 image 键记录。
- **键与失效链**：image_k 键 = crate 源 stamp（registry 源不可变，实际=版本+feature
  +rustc args）+ **栈下键链哈希** + MIRVM_BUILD_ID + 降低指纹。链哈希强制"构建时
  所见栈 = 装载时栈下"（FuncId 偏移与跨域地址的正确性前提，S4 base_key 的推广）。
- **最尖风险 = cargo 并行/流水线下的链一致性**：依赖 wrapper 并行跑，image_k 构建
  时"栈下"未必齐（cargo pipelining 下游可在上游 .rmeta 就绪即启动）。v1 缓解：
  **线性链纪律**——全局 lockfile 拓扑序定链；构建时装当刻已存在的最长前缀，键链
  如实记录；runner 装载取"键链前缀一致的最大集"，其余落 delta（自愈降级，不错值）。
  施工首日以 eco（22 crate 图）实测前缀命中率，不达标再议 barrier（wrapper 等待
  上游 image 文件，超时放弃）。
- **残余 delta** = bin 泛型在用户类型的实例化 + 跨 crate 混合泛型——正是 native
  编进 bin 的那份。预估 eco runner lower 988 → **100–300ms**（首日实测校正）。
- **成本记账**：成像时间 ≈ 把 988ms 摊进本就并行的 cargo 依赖构建相（S2 刚省下
  12% CPU，拿一部分换终身缓存的 image，跨项目共享——同 lockfile 的第二个项目
  白拿）。磁盘 ≈ 每依赖 0.1–1MB 级。
- **与 mode B 的关系**：S3′ 产物 = mode B `.mirvm` 包的机内形态；打包期只需把
  image 链 + delta 变可携带（外部格式冻结仍守 D9b 的"M5.3 后"门）。

### 3.4 终裁请求

采纳 C 为 S3 的产品归宿（S3′），A 记"不建 + 触发器"，B 否决。原 V3 在
coldstart-research §6 的行随裁定加注。

## 4. M5.3 JIT 骨架（D4/D5/D6 在 S4 世界的精化；已批部分不重开）

- **范围**（D4/gate6 原样）：翻译器标量子集（int/float/place/call/switch/SSA
  提升；两类局部——未取址标量升 SSA 变量，其余 Cranelift 栈槽）；两入口
  （packed `extern "C-unwind" fn(*const u64, *mut [u64;2])` + fast 纯 guest 签名）；
  T 骨架（R = 触发器活检查点，D5 终裁不动）；编译服务单线程持 JITModule。
- **S4 适配点**（本文新增的全部 JIT 内容）：
  1. PLT/计数表按**合并 FuncId** 尺寸建（absorb 之后 `funcs.len()`）；base 函数
     同等 tier-up（热点大头在 base：fmt/iter/alloc）。
  2. 翻译器读的常量/静态地址跨 0x6800/0x6900（未来 + image 样条）多域——对
     Cranelift 全是 64 位立即数，域无关；**机器码因此含跨域绝对地址 ⇒ §2.5
     不入缓存的第二条理由**。
  3. `call_guest` 在 warm 路径（absorb 后）与冷路径共用——L2/底座/未来 image 对
     JIT 完全透明。
- **unwind v1 准入**（D6 原案）：只收 unwind-transparent 函数（无 cleanup 边），
  spike5 CFI 管线（逐 FDE `__register_frame` + CIE 判别）产品化；LSDA/landing pad
  = M5.4（cg_clif GccExceptTable 同构，先 probe）。fib 锚点在准入内。
- **互操作清单**（逐条有既有机制，翻译器只需"调对助手"）：track_caller 幻影尾参
  （ABI 已冻结进 ParamAbi）；影子帧（JIT 帧入口/出口调 shadow push/pop 助手——
  v1 简化：JIT 帧也压合成 IP，backtrace 口径与解释一致）；TLS（TlsRef 走助手，
  D5 格②）；builtin/FFI/asm-stub（真地址直调，D1 既定）；CatchUnwind（宿主
  Builtin，编译帧调它 = 普通调用）。
- **CLI**：`--jit on|off`（默认 on）+ `MIRVM_JIT_THRESHOLD`（诊断用）。
- **oracle**：JIT-on == JIT-off == native 三重差分（既有 diff/corpus 通道双跑；
  gate6 原判据）。
