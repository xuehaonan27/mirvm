## 1. 一句话与验收锚点

M5.3 骨架的准入面是"标量子集 + unwind-transparent"——真实函数大多越界，JIT 用不上。
M5.4 把翻译器扩到**全 MIR 构造**（内存操作数/浮点/Div/Rem/128 位/SIMD/原子/广义 ABI/
track_caller），并让 **cleanup 边在 JIT 帧内着陆**（LSDA，cg_clif GccExceptTable 同构）。

**验收锚点（m5-design §4 M5.4 行，原判据）**：
1. `tests/m4_gate2.sh` unwind 九用例 **JIT-on 全过**（catch/Drop 顺序与 native 一致）；
2. **全量三重差分**：demo/corpus/diff_cargo 的 JIT-on == JIT-off == native（diff.sh 与
   diff_cargo.sh 的既有 JIT 双跑口径扩展）；
3. fib(32) 硬门不回退（M5.3b 实测 19.3ms；帧内存/LSDA 引入的成本记账，不回 80ms 线）；
4. gate5 全绿（数 +n 项 JIT 扩展行）。

## 2. 调研与 probe 结论（D6 先行令的答卷）

### 2.1 LSDA probe 全链通过（`src/vm/engine/jit_compile.rs::lsda_probe`，5/5）

链：try_call（tag0=cleanup，`BlockArg::TryCallExn(0)` 传异常指针）→ 手工
GccExceptTable → CIE(rust_eh_personality) + FDE.lsda → `__register_frame` →
宿主 resume_unwind 载荷 → **cleanup pad 在 JIT 帧内执行** → `_Unwind_Resume(exn)`
续传 → 宿主 catch_unwind 收到载荷。五个分支（宿主基线/import 直调/单帧 CFI/双帧
CFI/LSDA 全链）各自锁定一环。

### 2.2 三个实证发现（超 cg_clif 书面配方，决定施工正确性）

1. **rust 版 `find_eh_action` 对"ip 不在 call-site 表"返回 `EHAction::Terminate`**
   （std/src/sys/personality/dwarf/eh.rs:120 实证），phase 2 映射为
   `_URC_FATAL_PHASE2_ERROR`（静默 abort 无消息）——libgcc 的
   `__gcc_personality_v0` 同形输入返回 None。**故 call-site 表必须覆盖函数内全部
   调用点**（cg_clif 对无 handler 站点同样发 `landing_pad=0, action=None` 项的原因；
   probe 实测：只有 handler 项时，resume 后重过调用者帧的 ip 无项 → Terminate →
   abort；全覆盖后 rust_eh_personality 全链通过）。
2. **`extern "C"` 是 nounwind**（Rust 语义）：宿主经 fn 指针调 JIT 码必须用
   `unsafe extern "C-unwind"`——`extern "C"` 让调用闭包在 __rust_try 里无着陆垫，
   payload 静默越过 catch_unwind（probe 曾卡此数日；spike5 的 `CompiledFn` 同为
   C-unwind，旁证）。
3. **cg_clif 的完整配方在树在案**（`src/debuginfo/{unwind,gcc_except_table}.rs`）：
   CIE.personality = `rust_eh_personality`（DW.ref 间接）；`buffer.call_sites()` 是
   LSDA 唯一数据源（`FinalizedMachExceptionHandler::Tag(tag, landingpad)` + 空 handler
   站点）；`CallSite{start: ret_addr-1, length: 1, landing_pad, action}` 单字节项；
   `BlockArg::TryCallExn(0)` 即 pad 的异常指针块参。

### 2.3 M5.3 现状盘点（施工起点）

- 准入面（`jit_compile.rs::admit`）：Assign/AssignOverflow（slot 操作数）、IntBin
  （无 Div/Rem）/IntCmp/Cast/Not/Neg、SwitchInt 标量、Call（unwind=Continue 且 callee
  存在）——**无内存操作数（PlaceExpr/Mem/Ref/Copy 全拒）、无原子/浮点/128/SIMD、
  无 cleanup 边、callee ABI 全标量**。
- 帧模型 v1：全部槽提升 SSA 变量（I64 零扩到宽不变量），无栈帧内存。
- 两入口 + PLT（fast = n×I64 签名；packed = i2c `(*const u64, *mut u64)`）、c2i
  蹦床、CFI-only 注册管线（spike5 同源）、单 worker 编译线程 + 原子发布。

## 3. 设计

### 3.1 帧模型 v2（内存操作数的地基，一切的前提）

- **槽二分**：**被取址的槽**落**栈帧**（一个 `frame_size`/`frame_align` 的 Cranelift
  栈槽，按 ir::FuncBody 冻结几何；加载相已算好，JIT 直接复用）；**未被取址的槽**
  维持 SSA 提升（v1 不变量原样）。
  取址分析 v2 = **保守全集**：任何 `Ref`/`AddrOf`/`PlaceExpr::Local`/`Copy`/
  `MemCopy`/`RepeatBytes`/Indirect ParamAbi·RetAbi/`VolatileLoad|Store`/128 位 place
  通道触及的 frame offset 一律落帧（宁多勿漏——误提升 = 错值级，落帧只是慢一点）。
- **PlaceExpr 求值**（CLIF 直译）：base = Local（帧槽基址+off）/ Static（绝对地址
  立即数，冻结区真地址恒定）；steps：Deref（load W64）、Offset（常量）、IndexScaled
  （idx 槽值 × stride 加和）、VTableAlignOffset（meta 求值 + align 公式，与 interp
  同一恒等式）。
- **ScalarPlace::Mem / Operand::Mem**：按 width 的 load/store；**Copy/聚合**走
  CLIF `memcpy` libcall（与 interp 的 memcpy 语义同源）；RepeatBytes/RepeatScalar 同。
- 128 位 place 通道：CLIF `I128`（x86_64 reg-pair 承载），place 形状不变。

### 3.2 覆盖矩阵（op 族 → 处置；helper 与 interp 共享实现本体，不复制逻辑）

| 族 | 处置 | 备注 |
|---|---|---|
| IntBin 全家族（含 Div/Rem） | **内联**：Div/Rem 前显式零检 → 非零走 CLIF sdiv/udiv/srem/urem，零 → 调 `mirvm_jit_div_zero` 助手（诊断口径与 interp 一致） | interp int_bin 恒等式镜像，M5.3 既有模式延伸 |
| AssignOverflow/IntSat | 内联（M5.3 恒等式延伸） | |
| 浮点 f32/f64（FloatBin/Cmp/Neg/Cast/ToInt/FromInt/MathFma） | 内联 CLIF 原生（fma = CLIF fma 单舍入，与宿主 mul_add 同源） | |
| MathUn/MathBin（一元/二元数学） | **助手**=宿主 libm import（interp 的同一批符号直 import） | |
| f16 | **助手** `mirvm_f16_*`（interp 的宿主直算通道） | |
| f128 宽通道（F128* 全族） | **助手**=compiler-builtins `__*tf*` 符号直 import（interp 已降到同一批） | |
| 128 位整族（Bin128/Cmp128/Bit128(Count)/NicheDiscr128/Wide128ToFloat 等） | 内联 CLIF I128 + 少量助手（`__udivti3` 等） | |
| BitUn（ctpop/ctlz/cttz/bswap/bitreverse） | 内联 CLIF 原生 | |
| MemCmp | 助手=宿主 memcmp import | |
| MemCopy/MemSet | 内联 CLIF memcpy/memset libcall | |
| VolatileLoad/Store | **助手** `mirvm_volatile_{load,store}`（interp 的 alignment=1 opaque 字节载体+16/8/4/2/1 分块原样，防宿主解释 padding） | |
| AtomicLoad/Store/Rmw/Cxchg/Fence | 内联 CLIF 原子指令 + fence（MemOrd 五态直映；x86 上 Relaxed store 非 xchg，与 D8j 同源） | |
| SIMD（SimdBin/Un/Fma/Funnel/Cast/Select(Bitmask)/Splat/Gather/Scatter/MaskedLoad/Store/ExtractDyn/InsertDyn/Bitmask/Reduce(Arith)/ArithOffset） | 内联 CLIF 向量（逐族对表；LaneKind 类别约束同 interp） | 判为 CLIF 可净映射者 |
| x86 helpers（pshufb/sha256 系） | **助手**=interp 的 tcx-free stdarch target-feature helpers 同符号 | |
| CallBuiltin | **助手**：分配系 → `mirvm_alloc`（引擎堆同一入口）；unwind 系/宿主直通系/atexit/signal/fork 等 → c2i 回 interp（语义唯一权威） | CallBuiltin 的函数本体仍编译 |
| CallForeign（libffi 直通） | **助手** `mirvm_call_foreign`（经 interp 的 ffi 通道本体） | |
| CallIndirect（fn-ptr/dyn） | **助手** `mirvm_call_indirect`（fn_addrs 反查 + call_guest/native 兜底本体） | 内联缓存留 M5.5 |
| TlsRef | **助手** `mirvm_tls_ref`（Ctx.tls 惰性物化本体） | |
| InlineAsm | asm-stub 真地址直调（`fn(*mut u8)` 槽 ABI 同 interp） | |

| Ref/PtrOffset/PtrDiff/UMax | 内联 I64 算术（真实地址模型位透传） | |
| NicheDiscr（64 位） | 内联（interp 恒等式） | |

（与 interp 的 Trap 语义一致）；`Resume`/`TerminateAbort` 见 §3.4；`@entry`/argv
终结化不在 JIT 面（加载相职责）。

### 3.3 ABI 泛化（fast 签名 = 展平 I64 序列，镜像 interp ABI v2）

- ParamAbi：`Zst`=0 槽；`Scalar`=1；`Pair`=2；`Indirect{off,size}`=1 槽（src 地址，
  **callee 侧从帧槽 `off` 读 `size` 字节**——与 interp prologue memcpy 同语义）。
- RetAbi：`Zst`=0 返；`Scalar`=1 返；`Pair`=2 返；`Indirect`=调用方前插隐藏首参
  （sret 指针），callee 在 Return 时 memcpy `_0` → sret（同 interp）。
- `track_caller`：`caller_loc_off` 幻影尾参 +1 I64（调用方传 Location 指针；
  Reify shim 的 ABI 已由 lower 冻结，JIT 照抄展平序）。
- packed 入口随之泛化（(lo,hi) 写回 + sret 形态）。

### 3.4 LSDA 产品化（probe 配方的工程形态）

- **发射准则**：
  - `Call` unwind=**Cleanup(bb)** → `try_call`（normal=target block；异常表 =
    `[Tag(0, pre_pad)]`，pre_pad 带 `BlockArg::TryCallExn(0)` 块参）；
  - unwind=**Continue** → 普通 `call`（CFI 纯穿透，spike5 已验）；
  - unwind=**Terminate**（extern "C" ABI 边界）→ `mirvm_jit_unwind_abort` 助手
    （spike3 的跨 FFI abort 同语义）；
  - `Resume` → 从本函数 `exception_slot`（pre_pad 处 def）读异常指针，
    `call _Unwind_Resume` 后接 trap（cg_clif Resume 同构）；
  - `TerminateAbort` → `mirvm_jit_terminate_abort` 助手（诊断 + abort）。
- **LSDA 生成**（函数级，随编译批产出）：
  - 数据源 = `buffer.call_sites()`（**全覆盖**：无 handler 站点 →
    `(ret_addr-1, 1, lpad=0, action=None)`；cleanup tag →
    `(ret_addr-1, 1, pad, action=None)`——action 恒 None，Rust 无类型过滤）；
  - 版式 = probe 实证（lpStart=omit / ttype=omit / csEncoding=uleb128 /
    项按指令序（满足 rust 解析器有序表假设）/ 4 字节对齐）；
  - 挂接 = CIE 双轨：**无 try_call 的函数走 plain CIE**（今日管线不变），
    **有 try_call 的函数走 personality CIE**（DW.ref 间接 `rust_eh_personality`，
    lsda_encoding=absptr）+ `fde.lsda = <本函数 LSDA 地址>`；
  - LSDA 存储 v2 = **每函数 leaked Vec**（与 spike5/probe 一致；JIT data object
    留 M5.5——cranelift-jit 数据对象支持存在但 v2 不依赖）。
- **准入放开**：`admit` 从"op 白名单"改为"op 映射表全覆盖"（§3.2 每族有去处即收；
  `TerminateAbort`/`Resume` 所在函数必须有 cleanup 边才走 LSDA 轨，否则纯 CFI）。

### 3.5 oracle（第一原则，M5.3 同纪律升级）

1. **JIT-on == JIT-off == native 三重差分**（diff.sh/diff_cargo.sh 既有双跑口径）；
2. **逢调即编全量**（阈值=1，gate5 已有行）——所有可准入函数走编译帧，是误编译
   的第一显形处；
3. **gate2 unwind 九用例 JIT-on**（锚点判据①；catch/Drop 顺序与 native 一致）；
4. m51 系 tracer（addcarry/xgetbv/simd_insert/simd_shift/vzeroupper/x86_vectors）
   的 JIT-on 变体（SIMD/助手口径）；
5. fib(32) 硬门不回退 + eco engine 账本（探针的 per-crate 分布做 workload 选型）。

## 5. 风险表

| 风险 | 缓解 |
|---|---|
| 翻译器误编译（最尖） | 三重差分 + 逢调即编全量先于 native 显形；分批准入；op 恒等式与 interp 逐位镜像（M5.3 模式） |
| 取址分析遗漏（slot 误提升 = 错值级） | v2 保守全集（任何可能取址的 off 一律落帧）+ 双跑差分 |
| LSDA 覆盖遗漏一个 call-site（rust personality Terminate abort，probe 实证） | 生成准则 = `buffer.call_sites()` 全量迭代（数据源天然全）；gate2 九用例 JIT-on 必过；probe 模块留作最小回归 |
| helper 语义与 interp 漂移 | helper 一律调 interp/引擎本体（不复制逻辑）；Volatile/FFI/indirect/TLS 同 |
| 原子/SIMD 映射错位 | CLIF 语义核对 + m51 tracers JIT-on 双跑 |
| 性能回退（帧内存/助手/全覆 LSDA 注册成本） | fib 硬门不回退（80ms 线）+ 账本如实记；LSDA 仅 try_call 函数付 |
| 编译线程与发布的并发 | 维持单原子交换 + 只读码 + TSan interp-only（既有纪律） |

## 6. 开题问题（请裁）

- **Q1**：取址分析口径 = 保守全集（**建议**，任何可能取址的 off 一律落帧；M5.x 后
  视收益做逃逸精化）——还是一步到位做精确逃逸分析？
- **Q2**：128 位值 = CLIF `I128`（**建议**，reg-pair 自然映射；place 通道不变）——
  还是双 I64 半槽（更贴 v1 槽不变量）？
- **Q3**：LSDA 存储 = 每函数 leaked Vec（**建议 v2**，spike5/probe 同款）——还是
  JIT data object（M5.5 再评）？
- **Q4**：SIMD 范围 = CLIF 可净映射家族内联 + 其余/x86 helpers 走助手（**建议**）——
  还是 SIMD 全族先助手、逐族提内联？
- **Q5**：批次顺序 a→b→c→d（**建议**，LSDA 在 c 与 ABI 同片）——还是 LSDA 提前成
  独立片（若希望尽早锁定 unwind 风险）？
